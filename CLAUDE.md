# Kadabra Electronic Drumkit

HISE-based audio plugin (VST3 + AU on macOS, VST3 on Windows). Exported from HISE as a JUCE project; built per-platform via Xcode (macOS) and Visual Studio (Windows).

## Platform split

- **Windows binaries** are built on a separate Windows machine — not part of the Mac workflow, no signing/notarization needed here.
- **macOS binaries** (VST3 + AU component) are built on this Mac via Xcode, then must be manually signed and notarized (the Xcode project itself is set to `CODE_SIGN_IDENTITY = "-"` / ad-hoc, and hardened runtime is off in the HISE export settings, so none of this happens automatically).

## Build output

Xcode builds land at:
`Binaries/Builds/MacOSX/build/Release/Kadabra Electronic Drumkit.vst3`
`Binaries/Builds/MacOSX/build/Release/Kadabra Electronic Drumkit.component`

Both are flat bundles (no nested frameworks/dylibs), so a single non-deep codesign pass per bundle is sufficient.

## Signing & notarization workflow (macOS)

1. **Sign** with hardened runtime + entitlements (required for notarization even though the HISE/JUCE export has hardened runtime disabled by default):
   - Identity: `Developer ID Application: Amir Vinci (B74YHJSPSY)` (find via `security find-identity -v -p codesigning`)
   - Entitlements needed (from `Binaries/AutogeneratedProject.jucer` → `hardenedRuntimeOptions`): `com.apple.security.cs.allow-jit`, `com.apple.security.cs.allow-unsigned-executable-memory`, `com.apple.security.device.audio-input`
   - `codesign --force --deep --options runtime --timestamp --entitlements entitlements.plist --sign "Developer ID Application: Amir Vinci (B74YHJSPSY)" "<bundle>"`
2. **Zip** each signed bundle individually (`ditto -c -k --keepParent`) for notary submission.
3. **Notarize** via `xcrun notarytool submit <zip> --keychain-profile "kplayer-notary" --wait` — the `kplayer-notary` profile is already stored in this Mac's keychain.
4. **Staple** the ticket back onto the actual `.vst3`/`.component` bundles (not the submission zip) with `xcrun stapler staple`.
5. **Verify** with `spctl -a -vvv -t install "<bundle>"` — should report `accepted` / `source=Notarized Developer ID`.

## Samples monolith

Source of truth: `Samples/ElectronicDrumkitSampleMap.ch1`. This is what gets copied into distribution as `ElectronicDrumkitSampleMap.ch1`.

## Distribution

Live release folder (outside this repo, not in git): `/Volumes/Vinch2T/IMI/Releases/Kadabra Electronic Drumkit`

Contents: signed+notarized `.vst3` and `.component`, `ElectronicDrumkitSampleMap.ch1`, `Factory Presets/`, `INSTALL.txt`.

- Only update the plugin binaries and sample monolith unless told otherwise — leave `Factory Presets/` and `INSTALL.txt` alone.
- When zipping the release folder for distribution, use plain `zip -r -X` with `-x "*.DS_Store"` (not `ditto`, which pulls in `.DS_Store`). Name the archive `Kadabra Electronic Drumkit vX.Y.Z (macOS).zip`, where the version comes from the plugin's `Info.plist` (`/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" "Kadabra Electronic Drumkit.vst3/Contents/Info.plist"`).
- After zipping, sanity-check by extracting to a temp dir and re-running `spctl -a -vvv -t install` on the extracted bundles to confirm the notarization ticket survived.
